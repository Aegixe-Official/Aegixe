# 查黑 U 怎么查？收取 USDT 前的地址风险核查指南

[English](usdt-payment-risk.md) · [已发布 DEV 版本](https://dev.to/aegixe/cha-hei-u-zen-yao-cha-shou-qu-usdt-qian-de-di-zhi-feng-xian-he-cha-zhi-nan-9p5)

有人提出用 USDT 付款，发来余额截图，并保证资金“干净”。收款前，你究竟应该查什么？

**查黑 U 的实用流程是：先确认网络和真正的 USDT 合约，再核查付款地址、交易证据及相关限制。任何一个风险分数，都不能证明资金绝对安全，也不能保证交易所一定入账。**

这篇 AEGIXE 指南介绍收取 USDT 前的核查步骤，并解释经常被混称为“黑 U”的几类问题。

## “黑 U”到底是什么意思？

“黑 U”是中文加密社区里的非正式说法，通常指与涉嫌诈骗、盗窃或其他非法活动有关联的 USDT。有时，人们也用它描述被冻结的资金，或无法正常入账的充值。

它不是独立的代币标准，也不是所有钱包、交易所和风险服务都采用的统一技术分类。USDT 余额不会带着一个被所有平台一致识别的“黑色标记”。

核查前，应先区分四个问题：

| 问题 | 应当核查的内容 |
| --- | --- |
| 是不是真正的 USDT？ | 所在网络及发行方认可的代币合约 |
| 地址是否存在值得关注的关联？ | 风险标签、交易证据、归属依据及数据覆盖范围 |
| 地址目前是否受到发行方限制？ | 对应网络上的代币部署及当前限制状态 |
| 交易所会不会入账？ | 交易所支持的网络、充值规则及账户审核 |

真正的 USDT 仍然可能涉及交易对手风险；另一方面，即使地址查询没有提示风险，一个名字叫“USDT”的代币也可能是仿冒资产。

## 第一步：确认网络和 USDT 合约

先与付款方确认使用哪条网络。以太坊和 TRON 上的 USDT，不能因为名称相同就共用充值指引。

请以 [Tether 官方支持网络与集成指南](https://tether.to/en/supported-protocols/)中的合约资料为准。本篇核查时，官方页面列出的合约包括：

| 网络 | USD₮ 代币合约 |
| --- | --- |
| Ethereum | `0xdAC17F958D2ee523a2206206994597C13D831ec7` |
| TRON | `TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t` |

**上面是代币合约标识，不是让你转账付款的收款地址。** 请对照发行方的最新文档核实，不要长期只依赖文章里的副本。

在对应网络的区块浏览器中查看实际交易，核对代币合约、转账金额、双方地址和交易状态。代币名称、图标、余额截图或付款通知，都不足以单独证明资产真实或已经到账。

## 第二步：查询相关公开地址

收款前，尽可能取得预计付款的地址，并独立确认自己的收款地址。若款项已经到账，应以实际交易记录识别涉及的地址。

可以使用 [AEGIXE 地址风险查询工具](https://risk.aegixe.com/)作为核查起点：

1. 选择地址实际所在的区块链网络。本篇核查的界面包含 Ethereum 和 TRON。
2. 输入完整的公开地址。
3. 发起检测，阅读返回的信息及其限制说明。
4. 记录查询时间、风险提示，以及数据缺失或未覆盖的情况。

该工具界面说明，地址查询只需要公开地址，无需连接钱包或提供私钥。仅为取得风险查询结果，不应交出助记词、授权代币支出或签署交易。

地址查询也不能证明地址由谁控制。例如，共享的交易所提币地址，本身不能证明向你付款的人的身份。

## 第三步：看风险标签背后的证据

当服务商提示风险时，需要进一步确认：

- 标签指向被查询地址本身，还是间接关联的交易对手？
- 标签属于哪种风险，服务商如何定义这一类别？
- 是否提供交易哈希、资料来源或解释？
- 数据更新到什么时间？
- 服务是否覆盖对应网络和相关活动？

直接关联和间接关联不能混为一谈。地址还可能被动收到陌生转账，所以一条交易关联并不足以证明主观意图或违法行为。

不要自行设定一个通用的“安全分数线”。各服务商的数据集和模型不同。不支持的网络、查询失败或空结果，都代表仍有不确定性，不能自动当成“资金干净”。

关于风险评分的解读，也可阅读 AEGIXE 的[地址风险评分指南](https://dev.to/aegixe/crypto-wallet-address-risk-checks-what-a-score-can-and-cannot-tell-you-4jo2)。

## 第四步：区分风险筛查与 USDT 冻结

Tether 在 [2023 年 12 月 9 日的官方公告](https://tether.io/news/tether-introduces-new-policy-to-strengthen-ecosystem-security/)中，介绍了与 OFAC 特别指定国民名单相关的自愿钱包冻结政策。

这说明发行方限制是实际需要考虑的因素，但该公告不能证明某个地址目前被冻结，也不能证明所有网络的技术实现完全一致。

服务商给出的“高风险”标签，与发行方当前实施的限制，是两种不同的信息。未提示风险也不能证明不存在发行方限制。

如果这一点影响收款决定，需要依据可靠、对应网络的证据，核对相关代币部署的当前状态，并记录查询区块或时间。历史冻结事件、截图或旧标签，可能无法反映现在的状态。

转账失败也不能单独证明地址被冻结，因为失败可能有其他原因。同样，链上转账成功，并不保证后续向交易所充值一定入账。

## 第五步：保存可复核的核查记录

记录查询时间、网络、地址、提示原文和未知项。可选用[空白核查记录模板](../templates/README.md)；这是辅助记录示例，不是产品 API 或正式检测文件。 涉及私人的支付记录，应保存在适当的内部系统中，不要公开贴到 GitHub issue 或文章评论区。

如果重要风险提示无法解释，应暂停接受或继续处理该笔款项，并寻求适当复核。把资金转到另一个钱包，不能证明原有风险已经消失。

## 查黑 U 的常见问题

### 只有交易哈希，能查 USDT 风险吗？

交易哈希可以帮助你在对应网络中定位转账、代币合约和相关地址。它是调查起点，不能证明资金来源合法，也不能保证未来被平台接受。

### 收到有风险标签的 USDT，整个钱包就会自动冻结吗？

仅凭地址评分，不能得出这个结论。代币层面的限制、交易所账户限制，以及钱包中其他资产能否使用，是不同问题。应核查实际机制和证据，不能把一种结果套用到整个钱包。

### 先收一笔小额测试款，能证明后续款项安全吗？

不能。小额测试可能帮助确认转账路径，但不能证明后续大额款项的来源，不能消除交易对手风险，也不能保证平台接受。

### “未发现风险”是不是等于地址干净？

它只表示在本次查询覆盖的数据和时间范围内，没有识别出相关风险提示。新的交易、新的地址归属资料或不同服务商，都可能得出不同结果。
